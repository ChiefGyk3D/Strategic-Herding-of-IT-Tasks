# Strategic Herding of IT Tasks (SHIT)

SHIT is a portable, provider-neutral set of roles, packs and habits for people who are new to working with AI assistants. It is meant to work with whichever assistant you use, and it is staged so you can stop at any step: first habits (how to ask, check and record work), then a thin wrapper that applies those habits to every task, then delegation to several assistants with a human approving the result.

## Status

Private and pre-release. Nothing here is stable, the layout will change, and the text has not been edited for a public audience.

## Starter set (stage 1)

Four roles (implementer, reviewer, researcher, planner) and six packs (review-protocol, implementer-self-check, threat-model, python-untrusted-input, gha-security-dast, org-operating-model), generated by the installer of [department-of-internal-arguments](https://github.com/ChiefGyk3D/department-of-internal-arguments) at the commit pinned in `manifest.json`. Files for Claude (`.claude/`), Codex (`.codex/`, `.agents/`) and Copilot (`.github/agents/`) sit at the repository root; `prompts/` holds one paste-in prompt per role for a local model. Do not edit them by hand: change `scripts/refresh.py`, run `make refresh` and review the diff. `make check-refresh` reports drift without writing. The getting-started guide is a stub, see [docs/getting-started.md](docs/getting-started.md).

Local models are optional helpers for text-in, text-out work. See [docs/local-models.md](docs/local-models.md) for Ollama and LM Studio setup, measured hardware guidance, and the current integration status.

## Queue (stage 3, in progress)

SQLite is the only task, record, dependency, queue, and lease backend. The implementation is in `shit/store.py`, `shit/store_tasks.py`, and `shit/store_queue.py`; record bodies remain files by design. The queue rules are in [docs/queue-spec.md](docs/queue-spec.md), with implementation notes in [docs/queue.md](docs/queue.md).

The confined SQLite store, schema, fingerprint, error mapping, and operations are described in [docs/store.md](docs/store.md). Its hash-chained audit export, the offline verifier (`shit audit verify`) and the queue section of `shit check` are described in [docs/audit-export.md](docs/audit-export.md).

Bounded work (directory width, byte budget, scan and lock-hold deadlines) is described in [docs/bounded-work.md](docs/bounded-work.md).

## Review threads

`shit threads` validates a strict dispositions file and prints the exact `gh api` request plan for listing, replying to and resolving the review threads of any pull request; it never starts a process. A small launcher, `scripts/threads_run.py`, sits outside the package and runs the plan with the GitHub CLI when you run it yourself. See [docs/threads.md](docs/threads.md).

## Reviewer providers and tiers

The proposed provider-neutral reviewer policy, optional cyber-program tier, availability probes, adversarial quorum and fail-closed reporting are described in [docs/reviewer-tiers.md](docs/reviewer-tiers.md). This is a design note; it is not implemented.
